# 归账 · NAS 同步服务

自托管同步服务端。给一个「数据只存在自己 NAS 上」的记账 App 用的那一半。

当前服务端版本 **0.5.5**。新增收入分类结构和明细入口，继续支持电脑端导入与编辑、账户与投资、个人/家庭空间及 HTTPS。手机安装包不在本次发布中。

---

## 现在能做什么

- 配对换 token，10 分钟有效配对码
- 增量拉取 `GET /v1/changes?since=<seq>`
- 增量推送 `POST /v1/push`
- 字段级冲突合并（Lamport 时钟，不信设备墙上时间）
- 崩溃安全：日志先落盘再改内存，`kill -9` 后重放一致
- 重复推送幂等，超时重试安全
- 预算、规则、账本和周期提醒通过通用同步实体保存；标签和退款关联随账单同步
- NAS 面板按退款抵扣后的净支出统计，划转不计收入或支出
- 启动及每小时检查每日快照，保留最近 14 份；鉴权后可手动下载
- Go 同步核心无第三方依赖；镜像增加 Java 17 运行时，按需启动共用的安卓账单读取器

## 收入结构与分类明细（0.5.5）

首页点击“收入”进入收入构成，展示各分类的金额、占比和笔数；统计页可切换收入 / 支出。点击分类查看对应账单，再打开单笔详情和编辑。分类明细保留日期、账本等筛选范围。

`by_income_category` 与收入合计使用同一口径，`income_category` 用于只读下钻。有效关联退款抵扣原支出，账户划转和已删除记录不参与收入构成；未分类收入单独显示。未关联原账单的历史退款仍按现有收入记录展示，不根据备注猜测关联并改账。此功能不生成同步变更，不修改手机账单；家庭及个人空间继续隔离。

## 电脑账单导入（0.4.14）

进入面板「导入」，选择手机已同步的账本和账单文件，点击「读取并核对」。支持 CSV/TSV/XLS/XLSX/PDF/ZIP（20 MB 以内，单次最多一万笔），直接复用 Android core 的文件读取、格式识别及重复候选逻辑。预览不写入账本；原始文件不持久化，未确认预览 20 分钟过期，取消预览立即释放。缺少账户需要明确选择；保留原分类时补充缺失的两级分类；疑似重复默认不选，仍存在的强交易号重复不可选；同账本已删除的同交易号记录可勾选恢复原记录，保留原账户、分类和手动修改。缺少交易号的已删除记录不参与弱判重，允许重新导入。全选可导入账单会提示其中的疑似重复和待恢复数量。未支持借贷、复杂退款等行单独提示，必须确认已核对遗漏。

点击「确认导入并同步」后，账单与新增分类在同一批次中持久化并进入 `/v1/changes`。确认时重新核对最新数据；核对期间手机新增的重复候选会跳过。重试同一已提交预览返回原结果。手机自动同步时收到，也可以在手机 NAS 同步页点击「立即同步」。网页不会把“已保存到 NAS”显示成“手机已收到”；离线、受后台限制或未配对的手机无法由 NAS 强制唤醒。

多账本用户建议升级到 Android 0.1.42，新增分类的账本字段会随同步保留。费用、优惠和退款沿用手机端的保守识别规则；不同软件、不同导出版本未全部验证。图片、位置、完整债权债务与独立标签对象不在迁移范围。

从 GitHub 构建：`docker build -t kapi-sync:0.5.5 kapi-sync`。多阶段 Dockerfile 会独立编译 `import-worker` 的纯 JVM 读取器与 Go 服务，不依赖 Android SDK、本地 Gradle 缓存或手机源码改动。`import-worker/SOURCE-MANIFEST.json` 记录其共享核心来源及内容摘要。完整镜像基于固定摘要的官方 Eclipse Temurin 17 JRE；首次部署需要下载基础镜像，可提前拉取。只运行 Go 二进制仍可同步与查看，未配置读取器时导入页会明确提示组件缺失。NAS 内没有长期驻留的 JVM，读取与去重结束后进程退出。

错误行旁的「修正」允许调整本次预览的金额、时间、收支与币种，显示修改前值，保留原文件。修改后重新读取、校验并去重，重置所选账单和手工分类，必须再次核对。不支持的交易不会因勾选确认而变成普通支出，不能修改交易号等身份字段。

「批量映射分类」把所选新账单和疑似重复账单的原分类对应到现有分类，逐笔也可改选。映射受账本及收支类型约束，只有成功写入的手工选择才能记住；同一原分类映射到多个目标时不记忆。记忆保存在 NAS `meta.json`，随完整备份与恢复保留，手机收到的是最终分类。已存在和待恢复的记录保持原分类。

重复候选显示已有商户、金额、时间与账户，可打开原记录核对。页面分别显示原文件条数、修正行数、所选收支及实际入库收支。金额始终以整数分存储，超过两位有效小数的金额必须核对，不自动四舍五入。

导入接口：`GET /v1/panel/import/catalog`，`POST /v1/panel/import/preview`、`row`、`repair`、`commit`、`cancel`。修正与确认提交携带当前预览的 `revision`，过期版本拒绝提交。写请求必须提供 `X-Panel-Token`，不接受 URL 令牌代替；浏览器 Origin 必须与请求 Host 一致。所有写入均使用 Lamport/整数分/持久化日志协议。

## 跑起来

```bash
docker run -d --name kapi-sync \
  -v /volume1/docker/kapi-sync:/data \
  -p 8787:8787 \
  kapi-sync
```

默认以 HTTP 8787 兼容旧手机。面板地址为 `/panel/`，维护令牌可设置 `KAPI_PANEL_TOKEN`；未设置时自动生成并私密保存在 `/data/panel-token`，重启保持不变，日志不输出令牌或配对码。登录面板后再生成手机配对码。HTTPS 部署与家庭空间请见 [安全部署](DEPLOYMENT.md)。

本地开发：

```bash
go run ./cmd/kapi-sync -addr 127.0.0.1:8787 -data ./data
```

## NAS 账户与投资面板（0.4.10）

打开 `/panel/`，用原面板令牌登录。新增“账户”和“投资”入口：账户展示现金、负债、投资总资产、余额校准时间及是否计入净资产；投资按账户展示实际份额、移动平均成本、市值、持仓盈亏、已记录交易的已实现收益，以及买卖、分红、拆分、期初持仓的交易记录。持仓详情展示报价日期、来源和期初成本依据。沿用面板的玻璃卡片、浅色/深色主题、侧栏与窄屏底部导航。

`GET /v1/panel/assets` 使用面板令牌鉴权，可用 `account_id` 筛选。它只读取已同步数据和 NAS 已有行情缓存，不注册行情、不发起行情请求、不写账单。金额使用整数分，份额及价格使用精确十进制，费用、部分卖出成本分摊和清仓舍入与安卓保持一致。每个投资账户单独计算；已删除记录不参与估值。没有报价时市值显示待更新；现金尚未校准、缺少持仓报价、非人民币或设置为不计入净资产的账户不进入净资产合计。

新增持仓需要先在手机保存并完成 NAS 同步，面板不会自动获取券商的个人资产。测试数据仅用于隔离实例，不随镜像发布。本轮验证范围见 [0.5.4 发布说明](RELEASE-0.5.4.md)。

## 每日投资行情（0.4.8）

手机端从 Android 0.1.81 / iOS 0.1.18 起可直接读取公开基金净值和沪深股票、ETF 收盘价，无需配对 NAS。进入持仓页面时刷新，成功报价在 15 分钟内复用；手动刷新重新请求，不在手机后台轮询。仅发送资产代码，不发送份额、账户名称或交易金额。失败和较旧响应保留本机已有报价，不能把获取时间当作净值日期。NAS 为可选的同步及每日后台缓存，以下配置用于 NAS 自身的行情服务。

持仓和实际买卖由手机记录，行情服务只接收资产代码，不接收买卖金额或持仓份额。支持 `FUND:110022`、`SH:600519`、`SZ:000001` 等六位代码；沪深 ETF 使用相同市场前缀。

自己的 NAS 可设置 `KAPI_QUOTE_PROVIDER=eastmoney-personal` 启用个人公开行情。基金读取天天基金每日净值；股票优先读取东方财富不复权日线，断连或超时后切换腾讯证券不复权日线。商业发行需另行落实数据授权。保留原有 Tushare 配置，令牌只保存在 NAS 环境变量。

设备 Bearer 鉴权的 `GET /v1/investment/quotes?symbols=SH:600519,SZ:000001` 读取缓存并登记关注代码；同一路径 `POST` 等待本次刷新结果，18 秒请求预算。首次手机读取缺少报价时会等待一次刷新。报价使用十进制字符串，`date` 是交易日期，`fetched_at` 是最后成功更新时间，`last_attempt_at` 是最近尝试时间。失败保留原价、原交易日期和成功时间；返回 `error`。不接受复权价格、零价格、未来日期或比缓存更早的报价。

NAS 每十分钟检查是否需要刷新。全部使用北京时间：股票 15:15、基金 21:00 后启动当日更新。旧日期的成功响应会在发布窗口内重试（股票至 18:00，基金至当日结束）；失败自动五分钟后允许重试，下次检查执行。手动失败重试间隔三十秒，成功结果的手动刷新间隔十五分钟。未完成的当日日线不会作为收盘价。手机不进行后台轮询，相同缓存不会反复生成同步变更。这是每日收盘行情，不提供盘中实时价格。

本轮验证：服务端 88 项测试通过，报价与接口数据竞争检查通过；realme 的隔离持仓界面与正式 NAS 实际查询通过。定时调度通过跨时段测试，本轮未进行连续数日观察。

## iPhone 快捷指令（0.1 测试版）

`/shortcuts/` 提供连接 NAS、截图记账、手动记账、继续任务及确认与同步五个经过 Apple CLI 签名的模板。模板不含用户账单或凭据。截图通过 iOS 系统动作提取文字，NAS 负责规则解析、建议分类和最终保存；没有第三方图片上传或模型调用。

`GET /v1/shortcuts/catalog`、`POST /v1/shortcuts/preview`、`POST /v1/shortcuts/commit` 使用现有设备 Bearer 鉴权。预览只读，凭据签名绑定设备并在 24 小时后过期，确认提交采用现有 Lamport / 整数金额 / 持久化日志同步路径。同一个保存任务跨重试和重新配对仍只写一次，强交易号去重；相似交易需要明确核对。退款、划转、提现和外币截图首版拒绝直接入账。

快捷指令先由用户选择位置保存 JSON 任务再联网；失败或取消后用继续任务重新选择原文件。连接配置应放在“我的 iPhone/归账”，每次同步选择该配置；不要分享含设备令牌的配置文件。仅同一局域网或已有安全远程网络可使用 NAS 地址。

验证边界：72 项服务端测试与隔离 HTTP 联调通过，文件签名通过；Mac 原生网络动作出现等待异常，未完成原生端到端运行。已通过 USB 识别 iPhone 11（iOS 27.0），iPhone 镜像暂不可用，手机导入、OCR、文件与实际保存仍待实机验收。

生成模板：`python3 ../tools/build-shortcuts.py --output /path/to/output --sign`。`../tools/export-shortcut-rules.py` 从安卓分类规则同步 NAS 内置规则；生成的规则记录来源 SHA-256。NAS 内置模板位于 `internal/shortcutweb/files/`。

## 完整备份与恢复

面板点击“下载完整 NAS 备份”。ZIP 保存 `log.jsonl`、`meta.json` 与 SHA-256 清单，包含账本及设备配对状态，应保存在自己的存储中。自动备份位于 `data/backups/`，保留最近 14 份；手动下载也会生成一个快照。它与手机可分享的 JSON 账本备份格式不同。

恢复到空目录，然后切换容器的数据挂载；恢复会在临时目录校验 SHA-256、日志完整重放和序号，拒绝覆盖已有数据：

```bash
./kapi-sync -restore-backup /path/kapi-backup.zip -data /path/data-restored
```

升级前停止服务并备份整个 data、.env、Compose 及 tls；保留原镜像和配置用于回退。切换镜像后核对健康检查、空间权限、既有日志和实际手机同步。不要用旧数据覆盖升级期间的新写入。仓库中旧版通用部署脚本不是本次安全升级的自动执行入口，实际步骤见 [安全部署](DEPLOYMENT.md)。

## API

| | |
|---|---|
| `GET /v1/health` | 免鉴权。返回 `db_seq` / `rows` / `device_count`。`?pair_code=1` 附带当前配对码 |
| `POST /v1/pair` | `{pair_code, device_name}` → `{device_id, token, cursor}`。token 只返回这一次 |
| `GET /v1/changes` | `?since=<seq>&limit=<1..1000>` → `{changes, cursor, has_more}` |
| `POST /v1/push` | `{device_id, changes[]}` → `{applied, rejected, cursor}` |
| `GET /v1/row` | `?entity=&id=` 查单行，排查「这条到底谁改的」用 |
| `GET /v1/backup` | 设备鉴权，创建并下载完整 NAS ZIP |
| `GET /v1/backups` | 设备鉴权，列出保留快照 |
| `GET /v1/panel/backup` | 面板令牌鉴权，创建并下载完整 NAS ZIP |
| `GET /v1/panel/backups` | 面板令牌鉴权，列出保留快照 |
| `POST /v1/pair/code` | 需要鉴权。轮换配对码 |

设备 API 使用 `Authorization: Bearer <token>`；面板备份 API 使用 `X-Panel-Token: <KAPI_PANEL_TOKEN>`。`/v1/health` 和 `/v1/pair` 免鉴权，`/v1/backups` 与 `/v1/panel/backups` 返回 `{items: [...]}`。

### 变更格式

```json
{
  "change_id": "phone:t1:10",
  "entity": "txn",
  "entity_id": "t1",
  "op": "upsert",
  "data": { "amount_minor": 3200, "note": "早餐" },
  "fv": {
    "amount_minor": { "l": 10, "d": "phone" },
    "note":         { "l": 10, "d": "phone" }
  },
  "lamport": 10,
  "origin": "phone"
}
```

`fv` 是字段级版本戳，`l` 是 Lamport 计数，`d` 是设备 id。**`lamport` 不传或为 0 的 upsert 会被拒绝。**

没有 `fv` 的老客户端仍然能同步，只是退化成行级粒度（一台设备改任何字段都会覆盖整行）。

## 三条不能破的规则

写在代码里，也写在测试里。

### 1. 合并层永远不 import `time`

设备时钟会漂，用户还能手动改。拿墙上时间做「最后写入者胜」，合并结果会静默错乱，且**不报任何错**。`TestMergePackageNeverReadsTheClock` 用 `go/parser` 扫 import 列表强制这一点。

### 2. 墓碑是派生值，不是累积值

**行处于删除态 ⟺ 删除戳严格压过所有内容戳的最大值。**

不是「删了就置一个布尔位」。第一版就是这么写的，然后 720 种乱序测试里有两种顺序给出了不同答案：内容到 lamport 33 的行，墓碑戳还停在 16，于是一个 lamport 30 的删除被判赢并杀掉了它，反过来的顺序却复活了它。同一批变更，两种答案，零报错。

现在 `Deleted` 由 `recomputeState()` 算出来，不存、不累积、不可能漂移。撤销删除也顺带免费了。

### 3. 金额按字节原样透传

`data` 的值是 `json.RawMessage`，不是 `any`。

解进 `map[string]any` 会把所有数字变成 float64，于是 `amount_minor` 重启前是 `int`、重启后是 `float64`——一个持久化数据的静默类型变更，对金额来说正是 schema 明令禁止的浮点污染。`TestValuesRoundTripWithoutContamination` 用超过 2^53 的整数和 `0.1` 把它钉死。

## 已知取舍

**全量拒绝的推送也会进日志。** 一次字段全输的推送照样分配 seq 并落盘，所以 seq 增长会比「有效变更数」多。这是故意的——那是审计轨迹，而且如果 seq 只随合并结果走，客户端的游标算术就要依赖合并结果，那是个更糟的耦合。

**`replay()` 一次性读整个日志。** 个人账本几 MB，无所谓；超过 512MB 会打一条警告。压实是 v2 的事。

**`seen_change` 集合只增不减。** 每次改动几个字节，个人用量可忽略。

**传输层支持 HTTPS，但默认保留 HTTP 兼容入口。** 旧设备未迁移前仍是明文，不可宣称全设备加密。自有 CA 需要经过可信渠道核对，不应跳过证书校验。见 [安全部署](DEPLOYMENT.md)。

## 银行电子 PDF

0.4.13 与 Android 0.1.44 支持工行借记账户电子历史明细 PDF，最多 50 页、20 MB。本地读取内嵌文字，排除斜向水印，核对每页笔数和收支合计、同账户余额连续变化。余额只用于验证和稳定明细标识，不作为交易金额；银行序号不作为交易号。

普通消费、缴费、无卡支付以及工资、补贴、利息可核对后导入。充值、转账、汇款、信用卡还款、贷款、退款等含义不明确的明细会列出页码、时间、金额，暂不作为普通收支写入。必须选择实际银行卡账户并确认未导入明细。银行摘要缺少商户时分类需核对；与微信、支付宝同金额且时间接近的扣款只提示疑似重复。扫描 PDF 和其他银行版式尚未支持。

## 分类统计查看账单（0.5.2）

在 NAS 面板的“统计”页点击任意支出分类，可查看该分类的账单明细并继续打开单笔详情。保留当前时间、账本、搜索及其他筛选条件；“返回分类统计”退出分类明细。

明细与净支出统计使用同一口径：关联退款归入原消费分类，支持未分类与同名分类；不混入普通收入、账户划转或已删除账单。分页仅影响列表，不改变统计合计。

### NAS 0.5.3：编辑并同步原账单

在账单明细点击记录，选择“编辑账单”，可修改金额、同收支类型的分类、适用于该账本的人民币账户和备注。保存沿用原记录 ID 与交易号，手机下一次同步即可更新；可在手机点击“立即同步”。家庭共享账本只允许记账人修改自己的记录。其他设备在编辑期间修改过同一账单时，面板提示重新读取并核对。重复请求复用保存编号，网络重试不会创建新账单。原消费及关联退款的金额仍受可退金额约束，已删除账单不可从编辑入口恢复。
